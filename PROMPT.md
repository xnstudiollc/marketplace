# Master build prompt: "Vaultline" gaming marketplace

Paste everything below the line into a high-capability coding model (Cursor Agent mode). Keep this file in the repo so you can `@PROMPT.md` it in later chats.

## 0. Role and operating rules

You are a senior product engineer and UI designer. Build a complete, polished, front-end-only gaming marketplace called **Vaultline** (a placeholder brand; keep it in one constant so it is trivial to rename). It is a browsable catalog of games with marketplace-style listings (accounts, currency, items, boosting and services, keys and passes).

Operating rules:

1. Work in the phases in section 12. After each phase: run `npm run lint`, `npm run typecheck`, and (from phase 3 on) `npm run build`, fix everything, then `git commit` with a clear message. Do not move on with failing checks.
2. Do not stop to ask questions. Where this prompt is silent, choose the most conventional, high-quality option and note the decision in `DECISIONS.md` (short bullets).
3. Never invent games, categories, or listing types. Games come only from `data/games.json`.
4. No backend, no real payments, no real accounts, no network calls to third parties at runtime (fonts via `next/font` are fine).
5. Do not copy any real marketplace's branding, copy, or layout. Original design only. Do not use any real company's logo.
6. Everything must be typed (TypeScript `strict: true`, no `any`), accessible, and responsive from 360px up.
7. Prefer small, composable components. No file over about 300 lines.

## 1. Tech stack (use latest stable of each)

- Next.js (App Router, `src/` directory), React 19, TypeScript strict.
- Tailwind CSS v4 with CSS variables for design tokens.
- shadcn/ui (Radix primitives) for: Button, Input, Badge, Tabs, Select, Slider, Switch, Checkbox, Dialog, Sheet, Command (cmdk), Popover, DropdownMenu, Tooltip, Skeleton, Separator, Accordion, Avatar, ScrollArea, Sonner toasts.
- Framer Motion (`motion/react` import path if the installed package supports it).
- lucide-react icons.
- Zustand (with `persist`) for cart and recently viewed.
- Zod + React Hook Form for checkout.
- `next/font`: Geist Sans and Geist Mono (display headings may use Geist at heavier weights; no second family).
- Scripts in `package.json`: `dev`, `build`, `start`, `lint`, `typecheck` (`tsc --noEmit`), `data:build` (`node scripts/build-games-data.mjs`).

## 2. Data contract (source of truth)

`data/games.json` is generated by `scripts/build-games-data.mjs` from the raw export in `data/raw/games.raw.json`. If `data/games.json` is missing, run `npm run data:build` first. Never hand-edit `games.json`; edit `data/category-overrides.json` or the script and regenerate. Also generated: `data/categories.json` and `data/featured.json`.

Shape (copy into `src/lib/types.ts` as the single definition):

```ts
type CategoryId = "pc-console" | "online-mmo" | "mobile" | "ai-software" | "platforms-gift-cards" | "social-streaming";
type ListingTypeId = "accounts" | "currency" | "items" | "services" | "keys" | "other";

interface Game {
  name: string;
  slug: string;              // unique, URL-safe
  initials: string;          // 2 chars for fallback tile
  category: CategoryId;
  collection?: true;         // bucket entries like "Mobile Games", "Other Games", "VR Games"
  listingTypes: ListingTypeId[];             // ordered, drives the tabs on the game page
  labels: { name: string; type: ListingTypeId }[];  // original sales labels, e.g. "Kinah", "Battle Pass", "Top Up"
  variants?: string[];       // server / region / edition groups, e.g. "EU, NA", "Free"
  experiences?: string[];   // sub-games (Roblox only): render as filter chips, NOT as separate games
}
```

Rules for using the data:

- Tabs on a game page are exactly `game.listingTypes`, in that order, labelled: accounts = "Accounts", currency = "Currency", items = "Items", services = "Boosting & Services", keys = "Keys & Passes", other = "Other".
- Inside a tab, `labels` of that type become sub-filter chips (for example the Currency tab of an MMO shows chips "Gold", "Silver"; the Keys & Passes tab shows "Keys", "Top Up", "Battle Pass").
- `variants` render as a segmented "Server / Region" selector above the listings and filter the mock listings.
- `experiences` render as a searchable chip row on the Items and Accounts tabs.
- `collection: true` games get a tile with a stacked-cards motif, are excluded from "Featured" and from the A to Z letter counts' "popular" styling, and their page shows a short note that it groups many smaller titles.
- Load the JSON at build time in server components. For client search, pass only `{ name, slug, category, initials }` (about 25 KB), never the full dataset.

## 4. Visual design system

### 4.1 Mood

Dark, premium, "esports lounge meets fintech". Deep blue-black canvas, soft aurora glows behind content, glass panels, crisp 1px hairlines, restrained neon accents used only for interaction and emphasis. It should feel expensive and calm, not loud. Avoid rainbow gradients, heavy drop shadows, and cartoon gaming tropes.

### 4.2 Color tokens (define as CSS variables in `globals.css`, expose in Tailwind theme)

```
--bg:            #07080D   /* page */
--bg-elevated:   #0C0E16   /* sections */
--surface:       rgba(255,255,255,0.04)   /* glass fill */
--surface-hover: rgba(255,255,255,0.07)
--border:        rgba(255,255,255,0.08)
--border-strong: rgba(255,255,255,0.16)
--text:          #F3F5FA
--text-muted:    #9AA3B8
--text-subtle:   #6B7490
--accent:        #7C5CFF   /* violet, primary */
--accent-2:      #22D3EE   /* cyan, secondary */
--accent-3:      #F472B6   /* pink, rare highlight only */
--success:       #34D399
--warning:       #FBBF24
--danger:        #FB7185
--ring:          rgba(124,92,255,0.55)
```

Per-category accent used for glows, chips and tile tints: pc-console `#38BDF8`, online-mmo `#7C5CFF`, mobile `#F472B6`, ai-software `#22D3EE`, platforms-gift-cards `#FBBF24`, social-streaming `#34D399`.

Contrast: body text must meet WCAG AA on every surface. Never place `--text-muted` on a glow.

### 4.3 Background

- Fixed full-viewport layer: `--bg` plus two large blurred radial gradients (violet top-left at about 18% opacity, cyan bottom-right at about 12% opacity), each 60vmax wide, `filter: blur(120px)`, very slow drift animation (60s, `translate` only, disabled under `prefers-reduced-motion`).
- A 2% opacity noise texture (inline SVG data URI, no image file) over the top to kill banding.
- A faint 64px grid mask fading to transparent by 70% viewport height, only on the Home hero.

### 4.4 Glass recipe (build as `<GlassCard>` plus a `.glass` utility)

```
background: var(--surface);
border: 1px solid var(--border);
backdrop-filter: blur(14px) saturate(140%);
box-shadow: inset 0 1px 0 rgba(255,255,255,0.06), 0 8px 30px rgba(0,0,0,0.35);
border-radius: 16px;
```

Variants: `subtle` (no blur, for dense lists), `raised` (stronger border, for modals), `interactive` (adds the hover glow below). Fall back to a solid `#10131C` fill when `backdrop-filter` is unsupported.

### 4.5 Glowing hover accent (the signature interaction)

On `interactive` cards and game tiles:

- A radial highlight follows the cursor: set `--mx` and `--my` from `onPointerMove`, render `radial-gradient(240px circle at var(--mx) var(--my), color-mix(in srgb, var(--card-accent) 28%, transparent), transparent 70%)` in a pseudo-element masked to the border for a lit-edge effect, plus a softer fill glow inside.
- On hover: border color moves to `color-mix(in srgb, var(--card-accent) 55%, transparent)`, card lifts `translateY(-3px)`, outer glow `0 0 0 1px` + `0 12px 40px -12px var(--card-accent)` at 35% alpha.
- Touch devices: no cursor tracking; use a brief 200ms accent border flash on press.
- All of it off under `prefers-reduced-motion` (keep only the border color change).

### 4.6 Typography

Geist Sans. Scale: hero `clamp(2.5rem, 6vw, 4.75rem)` weight 700, tracking -0.03em, line-height 1.02; h1 `2.25rem`; h2 `1.5rem`; h3 `1.125rem`; body `0.9375rem/1.6`; caption `0.8125rem`. Numbers (prices, counts) use `font-variant-numeric: tabular-nums` and Geist Mono for order numbers. Hero headline uses a subtle text gradient from `--text` to `#B8C0FF`.

### 4.7 Shape, spacing, elevation

8px spacing grid. Radii: chips 999px, inputs and buttons 12px, cards 16px, modals and sheets 20px. Max content width 1280px, gutters 16px mobile, 24px tablet, 32px desktop. Section vertical rhythm 72px desktop, 48px mobile.

### 4.8 Motion (Framer Motion)

- Easing: `[0.22, 1, 0.36, 1]` for entrances; springs `{ type: "spring", stiffness: 380, damping: 32 }` for taps and layout changes.
- Page sections fade and rise 16px on first view (`whileInView`, `once: true`, 450ms), grids stagger children by 40ms (cap total stagger at 400ms).
- Tabs: animated underline/pill via `layoutId`.
- Cart drawer: slides from right, items enter with 8px rise; "Add to cart" button morphs to a checkmark for 1.2s and the header cart badge does a spring bump.
- Number changes (cart total) cross-fade with a 120ms vertical slide.
- Skeletons shimmer (1.6s linear) only where data is actually deferred; never fake loading on static data.
- Respect `prefers-reduced-motion` globally (a `useReducedMotion` guard and a CSS media query).

### 4.9 Components: look and behavior

- **Buttons**: primary = violet to indigo gradient fill, white text, inner top highlight, glow on hover; secondary = glass; ghost = text only with surface-hover on hover. Min touch target 44px. Visible 2px focus ring using `--ring` with 2px offset.
- **Chips**: pill, glass fill, 13px text, selected state = accent border + 12% accent fill + check icon (not color alone).
- **Inputs**: glass fill, 1px border, focus ring, leading icon slot, clear button when non-empty.
- **Badges**: tiny uppercase tracking 0.06em labels such as "Instant delivery", "Verified", "Top seller", "Sale".
- **Tooltips** only for icon-only buttons.
- Icons: lucide, 18px default, stroke 1.75.

## 5. Game artwork and the asset fallback system

Games ship without images. Real logos may be added later at `/public/games/{slug}/logo.png`. The UI must look intentional both ways and must never produce a 404 in the console.

- Build time: a small script (`scripts/index-game-assets.mjs`, run in `predev` and `prebuild`) scans `public/games/*/logo.png` and writes `src/generated/game-assets.json` as `{ [slug]: true }`. `<GameImage>` checks this map synchronously, so no failed network request ever happens.
- If an asset exists: render `next/image` (`object-fit: contain`, on a tinted glass plate, sizes tuned per usage).
- If not: render the **generated tile**:
  - Hue derived from a stable hash of the slug (cyrb53 or FNV-1a), constrained to a palette that reads well on dark: HSL saturation 70 to 85%, lightness 45 to 58%.
  - Two-stop diagonal gradient (hue and hue+38), with a faint conic sheen and a 1px inner border.
  - Centered `game.initials` in Geist 700, tracking -0.02em, white at 92% opacity, with a soft text shadow. Size scales with the container (use container query units).
  - For `collection: true`, add two offset ghost cards behind the tile.
- Sizes: `sm` 40px (lists, search), `md` 72px (cards), `lg` 120px (game hero). Squircle radius 22%.
- Provide a Storybook-free `/dev/tiles` route (excluded from sitemap, `noindex`) that renders 60 tiles to eyeball variety; delete it from production via `notFound()` when `NODE_ENV === "production"`.

## 6. Pages in detail

### 6.1 Home `/`

1. **Hero** (about 80vh desktop): eyebrow chip "Marketplace for gamers" (original copy), gradient headline (for example "Everything for your next level, in one place"), one supporting sentence, a large search field (`Command`-style trigger, shows `Cmd K` hint on desktop) that opens the palette, and two buttons: "Browse all games" and "How it works". Beneath: a trust row of 4 glass stat pills computed from real data (total games, total categories, "Instant delivery items", "24/7 support" as static copy). A slow-moving marquee row of 12 generated game tiles under the hero (pause on hover, hidden under reduced motion).
2. **Category chips row**: 6 categories with per-category accent icon, game count, horizontally scrollable on mobile with snap.
3. **Featured games** grid from `data/featured.json`: 2 cols mobile, 3 tablet, 4 desktop. Each card: tile, name, category chip, listing type icons, "From $X" mock price, hover glow.
4. **"What are you looking for?"**: 5 large glass tiles for the listing types (Accounts, Currency, Items, Boosting & Services, Keys & Passes), each showing how many games support it and linking to `/browse?type=...`.
5. **Trending now**: horizontal scroll rail of 12 deterministic picks (seeded by the current ISO week so it changes weekly but is stable between builds).
6. **How it works**: 3 steps with numbered glass cards and a connecting line that draws on scroll.
7. **A to Z browser**: sticky letter rail (A to Z plus `#`), letters with no games are disabled; clicking scrolls to a section; each section is a compact grid of small tiles. On mobile the rail is a horizontally scrollable pill bar pinned under the header.
8. **Seller spotlight**: 4 mock sellers with avatar, rating, completed orders, response time.
9. **FAQ** (Accordion, 6 questions) and a final CTA band.

### 6.2 Browse `/browse` and `/category/[id]`

- Left filter panel on desktop (sticky), bottom Sheet on mobile with an active-filter count badge on the trigger.
- Filters: text search (fuzzy, debounced 150ms, matches name and initials and label names), category (multi), listing type (multi), "Has variants" switch, sort (A to Z default, Z to A, Most listing types, Newest-looking = deterministic shuffle).
- URL is the state: `?q=&cat=&type=&sort=` using `nuqs` or a small typed `useSearchParams` helper. Shareable and back-button friendly.
- Result grid shows count ("143 games"), uses `content-visibility: auto` plus "Load more" in batches of 48 (no infinite scroll that fights the footer). Empty state with an illustration made from tiles and a "Clear filters" button.

### 6.3 Game page `/games/[slug]`

Layout, top to bottom:

1. **Breadcrumb** (Home / Category / Game).
2. **Hero**: large tile (lg), H1 game name, category chip, row of listing-type badges, mock stats (offers count, sellers count, average delivery time), a "Notify me about deals" ghost button that toasts. Glow tinted with the category accent. Add a faint oversized, blurred copy of the tile behind the hero as ambience.
3. **Server / Region selector** (if `variants`): segmented control, plus "All". Persist in the URL as `?v=`.
4. **Tabs** = `listingTypes`. Active tab in the URL as `?tab=`. Tab content:
   - Left (desktop sticky): filters card: price range Slider, delivery (Instant / under 1h / any), seller rating (4+ / 4.5+), "Online sellers only" Switch, label chips from `labels` of this type, `experiences` chips if present, sort select (Recommended, Price low to high, Price high to low, Rating, Fastest delivery).
   - Right: list of **Listing cards** (section 6.4) with result count, and "Load more" in batches of 12.
5. **Sidebar summary (desktop)**: "Why buy here" glass card (buyer protection, instant delivery, support).
6. **Related games**: 8 games from the same category, seeded by slug.
7. Mobile: tabs scroll horizontally with snap; filters live in a bottom Sheet; sticky bottom bar shows lowest price and a "Filters" button.

### 6.4 Listing card

Horizontal glass row on desktop, stacked on mobile.

- Left: seller avatar (generated initials tile), name (link), verified tick, rating (star + number + review count), online dot, response time.
- Center: title (generated, see section 8), 2 to 3 attribute chips relevant to the type (for example server, quantity, level, rank, platform), delivery badge ("Instant" or "~25 min").
- Right: price in large tabular numerals, per-unit price for currency ("$0.84 per 1M Gold"), quantity stepper for currency and keys, primary "Buy now" and secondary "Add to cart".
- Hover: accent glow in the listing's type color. Sale items show a struck-through original price and a "-18%" badge.
- Clicking the card opens a **Listing details Dialog** (not a new route) with full description, delivery steps, seller card, and the same buy actions.

### 6.5 Seller profile `/sellers/[id]`

Banner with seller-seeded gradient, avatar, name, verified badge, member since, stats (rating, completed orders, response time, completion rate), a "Games" chip row, tabs "Offers" and "Reviews". Reviews: rating distribution bars, 12 deterministic reviews with relative dates, helpful buttons that only change local UI state.

### 6.6 Cart (Sheet and `/cart`)

Zustand store: add, remove, set quantity (min 1, max 99 or the listing stock), clear, persisted to localStorage with a version key. Grouped by seller. Shows subtotal, a mock "service fee" (4.5%), total, empty state with suggested games, and a "Checkout" button. Header badge shows item count. Optimistic toasts with Undo for remove.

### 6.7 Checkout `/checkout` and `/checkout/success`

Two-column: form left, order summary right (summary collapses into an Accordion on mobile).

- Fields (Zod validated, errors inline, `aria-describedby`): email, in-game username or character name (per item if it needs delivery details), delivery notes (optional), payment method as a radio-card group (Card, Wallet balance, Crypto: all mock), card fields shown only for Card (number with Luhn check, expiry MM/YY not in the past, CVC), terms checkbox.
- Submit shows a 1.2s button loading state, then clears the cart, stores a mock order `VL-XXXXXX` (Geist Mono) in `sessionStorage`, and redirects to the success page. A banner on the checkout page states clearly: "Demo only. No payment is processed."
- Success page: animated check, order number, summary of items, "Back to browsing" button. If opened with no order in session, redirect to `/`.

### 6.8 Command palette (Cmd/Ctrl+K)

shadcn `Command` in a `Dialog`. Groups: Games (top 8 by fuzzy score, with tile and category), Categories, Pages. Keyboard: arrows, enter, escape; shows recent searches (localStorage, max 5). Debounced fuzzy search over the lightweight index (use `fuse.js` or a tiny custom scorer weighting prefix matches highest; handle apostrophes and punctuation by comparing against the slug as well).

### 6.9 Header and footer

- Header: logo mark (inline SVG, original, a simple hexagon vault door glyph) plus wordmark, nav links (Browse, Categories dropdown with accent dots, Help), search trigger, cart button with badge. Glass, `sticky top-0`, shrinks from 72px to 60px with a stronger border after 8px scroll. Mobile: hamburger opens a full-height Sheet with the same links and search.
- Footer: 4 link columns, newsletter input (mock), small print noting this is a demo, back-to-top button.

## 7. Responsive behavior

Mobile first. Breakpoints: 360, 640, 768, 1024, 1280, 1536. Required checks at 360, 390, 768, 1024, 1440. No horizontal page scroll anywhere. Tap targets at least 44px. Sticky elements must not overlap each other (header 60px plus filter bar). Use `dvh` for full-height layouts. Safe-area insets on bottom bars. Images and tiles never overflow. Long game names truncate to 2 lines with `line-clamp-2` and a `title` tooltip.

## 8. Deterministic mock data (no randomness at runtime)

Create `src/lib/mock/` with:

- `rng.ts`: `hash(str) -> uint32` (FNV-1a) and `mulberry32(seed)`. Every generated value derives from `slug`, tab, and index. Same input, same output, on server and client, across rebuilds. Never call `Math.random()` or `Date.now()` during render.
- `sellers.ts`: a pool of 36 fictional sellers (invented handles such as "NovaTrade", "QuietFalcon", "ByteMonk"; do not use real brand or streamer names). Each: id, handle, avatar tile hue, rating 4.1 to 5.0 (weighted high), review count, completed orders, response time, verified flag, member-since year, languages, online flag (seeded).
- `listings.ts`: `getListings(game, type, variant?)` returns 10 to 40 listings per tab depending on how rich the game is (more labels, more listings). Fields: id, sellerId, title, type, labelName, price (USD, 2 decimals), originalPrice?, unit?, stock, deliveryMinutes (0 = instant), attributes, description, createdOrder.
  - Title templates per type, for example currency: "{qty} {label} | {server} | Fast", items: "{label}: {adjective} {noun}", accounts: "Level {n} account with {perk}", services: "{label} by a top player", keys: "{label} key (Global)". Use varied but tasteful vocabulary; avoid slurs or real-money-trading claims.
  - Price ranges: accounts 8 to 400, currency per-unit scaled so totals land at 2 to 300, items 1 to 250, services 5 to 150, keys 4 to 80. About 15% of listings are on sale (10 to 30% off).
- `reviews.ts`: 12 reviews per seller from a bank of about 40 short, realistic review sentences, with seeded relative dates ("3 days ago", "2 weeks ago", "5 months ago" computed from a fixed anchor date constant, not `Date.now()`).
- `stats.ts`: per-game offers count, sellers count, median delivery time (derived from listings, so numbers on cards and pages agree).

All prices formatted with `Intl.NumberFormat("en-US", { style: "currency", currency: "USD" })`. Show a small "Demo data" badge in the footer.

## 9. Performance, SEO, accessibility

- Static generation for every route that can be static; verify `next build` output lists all `/games/[slug]` pages. Keep client JS lean: server components by default, client components only for interactive islands.
- LCP under 2.5s on a throttled mobile profile for Home; avoid layout shift (reserve tile space, `font-display: swap` via `next/font`). `content-visibility: auto` for long grids.
- Metadata API per page: title template `%s | Vaultline`, description generated from game data, canonical URLs, Open Graph defaults using a generated `opengraph-image.tsx` (gradient background plus name) for the site and for games. `robots.ts` and `sitemap.ts` including all games.
- Accessibility: semantic landmarks, skip link, visible focus, full keyboard operation of tabs/menus/dialog/palette, `aria-live` for cart announcements, labels on all inputs, color is never the only signal, reduced motion supported. Target Lighthouse accessibility 95 or higher.
